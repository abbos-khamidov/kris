# Архитектурные решения

## ADR-001 Две реализации хранилища (Supabase + локальная демо)
Credentials Supabase отсутствуют на момент разработки. Весь код ходит через интерфейсы `Db`/`Storage`. `supabase` — боевая реализация (RLS, приватные buckets). `local` — файловое хранилище `.data/` для демо и тестов; на Vercel не используется (эфемерная ФС). Режим выбирается по наличию `NEXT_PUBLIC_SUPABASE_URL`.

## ADR-002 Локальная авторизация в демо-режиме
Пароли — scrypt с солью, сессия — HMAC-подписанная httpOnly cookie, секрет из `SESSION_SECRET` (либо генерируется в `.data/`). Захардкоженных паролей нет: первый пользователь создаётся на странице первичной настройки, пока в базе нет пользователей.

## ADR-003 Один PDF-рендерер, генерация на клиенте
`@react-pdf/renderer` работает и в браузере, и в Node. Предпросмотр, скачивание, шаринг и утверждение используют один `CardDocument` и один `CardSnapshot`. При утверждении PDF генерируется в браузере и загружается в приватное хранилище по signed upload URL; сервер фиксирует snapshot и метаданные (хэш, размер). Это исключает тайм-ауты Vercel Functions и расхождения между предпросмотром и файлом. Предпросмотр показывает страницы того же PDF, растрированные через pdfjs-dist (iOS не умеет PDF в iframe).

## ADR-004 Шрифты
Референсы сверстаны Prata (заголовки) и Manrope (текст). Оба OFL, кириллица, символ ₽. Статические TTF из `@expo-google-fonts/*` лежат в `public/fonts`, встраиваются в PDF.

## ADR-005 Неизменяемость
Медиафайлы не перезаписываются: замена = новый `media_assets` + новый путь. Snapshot хранит id и путь конкретной версии, плюс копию данных карты, цен, каталога, настроек. Утверждённый PDF хранится как файл, скачивание отдаёт его же.

## ADR-006 Композиции референсов
Страница 595×822 pt. Фон страниц 3–10 — размытая фотография + белая скруглённая карточка. Заголовки Prata, бордовые (#791F2B) на светлом и белые на тёмном фоне; на страницах 2, 8, 9 слева вертикальная фирменная надпись; на 5–7 справа фото. Страница 2 — шкала себосекреции 1–5; страница 4 — иллюстрация лица, зелёная/красная легенда; страница 8 — таблица «название — цена»; страница 9 — три колонки (номер, описание, цена); страница 10 — фото специалиста, кнопка «Связаться со мной». Обложка: три варианта (белая рамка сверху, бордовый низ, бордовый верх+низ).

## ADR-007 Фирменные изображения
Фото в референсах — постоянные элементы шаблона, а не фото пациентов. Они хранятся в централизованной библиотеке фирменных изображений (роли: обложка, фон, иллюстрация лица, косметика, питание, витамины, специалист), подставляются во все карты автоматически и заменяются в настройках (с кадрированием). Фотогалерея пациента необязательна, в PDF не попадает автоматически. Оригиналы, извлечённые из референсов, лежат в приватном хранилище/`assets-private/`, не в Git.

## ADR-009 Голосовой ввод (P0)
Компонент `VoiceInput` + единый интерфейс `SpeechProvider` (`src/lib/speech/`). MVP-провайдер — Web Speech API (ru-RU), промежуточный и итоговый текст, таймер, индикатор. Предусмотрен провайдер локального Whisper (не реализован, интерфейс готов). Важно: в Chrome Web Speech API отправляет аудио на сервер Google — перед первым использованием показывается явное предупреждение, режим включается только по согласию специалиста; без поддержки/разрешения работает обычный ввод. Аудио не сохраняется. Текст вставляется в позицию курсора / в конец / вместо выделения только после подтверждения в предпросмотре, есть «Отменить последний голосовой ввод». Режим «Надиктовать консультацию» распознаёт явные названия разделов («Состояние кожи», «Утренний уход» …) как переключатели и **не** структурирует текст интеллектуально; названия препаратов, дозировки и единицы не изменяются.

## ADR-010 Блочная модель документа
Каждая рекомендательная часть страницы — массив блоков: заголовок, абзац, нумерованный/маркированный список, таблица, изображение, примечание, индивидуальный блок. Блоки добавляются, удаляются, перемещаются, дублируются; заполняются вручную, голосом или из библиотеки. Инлайн-разметка в тексте: `**жирный**`, `==бордовый==`, `!!важное!!`. Структура 10 страниц фиксирована; при переполнении рендерер добавляет страницы-продолжения.

## ADR-011 UI: редакторский минимализм
Швейцарская типографика, молочный фон, бордовые акценты, тонкие нейтральные границы, радиус 6 px, без стекла/градиентов/декоративных иллюстраций/фиктивной статистики. Рабочий экран карты — три области: навигация по разделам · редактор раздела · предпросмотр PDF; на телефоне — переключение сегментами.

## ADR-012 Библиотека и память
Поиск по ранее утверждённым рекомендациям (текстовые блоки из утверждённых версий индексируются обезличенно), избранные и частые шаблоны, вставка фрагмента прошлой карты, сохранение как обезличенный шаблон. Новые референсы расширяют понимание структуры, но не становятся утверждёнными протоколами автоматически.

## ADR-013 Адаптивность, синхронизация, PWA, QA
Единая кодовая база; три сценария: desktop (навигация · редактор · PDF с изменяемой шириной панелей, сворачиванием, горячими клавишами), планшет (альбом — рядом, портрет — переключатель), телефон (пошаговые разделы, полноэкранный PDF, закреплённая панель действий над клавиатурой, цели ≥44 px, safe-area). Пасхалка: sidebar на desktop, меню профиля на планшете/телефоне.
Сохранение: debounce-автосохранение, оптимистичная блокировка по `updated_at` (`Db.update(..., {ifUpdatedAt})` → `ConflictError`), статус «Сохранено» показывается только после ответа сервера; при обрыве сети правки остаются в памяти страницы, показывается «Нет соединения», повтор при `online`; предупреждение о несохранённых изменениях при уходе. Последний открытый раздел и тема хранятся в Supabase (`settings`, ключ `ui`).
PWA: manifest + service worker, кешируются только статические ресурсы (`/_next/static`, шрифты, иконки); запросы к данным, Storage, `/api/*` и PDF не кешируются никогда.
PDF не зависит от экрана, ориентации и темы сайта: отдельные константы в `src/pdf/tokens.ts`, тест запрещает импорт темы в `src/pdf`. Предпросмотр поддерживает масштаб, перелистывание и pinch-zoom.
QA: Playwright (Chromium, WebKit, Firefox) на 10 разрешениях; совместимость заявляется только по реально выполненным проверкам, реальные iOS/Android — вручную.

## ADR-008 Импорт карт
Массовая загрузка PDF → pdfjs-dist (текст, позиции, изображения) → классификация 10 разделов → структурированный черновик для проверки. Источник, дата импорта и статус проверки сохраняются. Персональные данные отделены от обезличенной базы знаний. Блоки и продукты попадают в шаблоны/каталог только после подтверждения специалистом; дубликаты отсекаются нормализованным хэшем. OCR не используется, пока не понадобится.

## ADR-014 Cache Components отключены
Шаблон Next 16 включает `cacheComponents`. Все данные приложения приватные, пользовательские и динамические; кеширование страниц запрещено принципами проекта (медданные не кешируются). Поэтому `cacheComponents` и `partialPrefetching` отключены, страницы с данными помечаются `dynamic = "force-dynamic"`.

## ADR-015 Lint: одно осознанное исключение
Правило `react-hooks/set-state-in-effect` отключено: наши эффекты загружают данные с сервера и сбрасывают локальное состояние загрузки в начале — React допускает это, правило касается стоимости рендера, а не корректности. Правило `refs` соблюдается; единственное исключение — шаблон «latest ref» в `use-autosave.ts` (замыкание вызывается таймерами, не при рендере).

## ADR-016 Развёртывание: Vercel + Supabase (бесплатные тарифы)
Только публичный (publishable) ключ Supabase; сервисные ключи не используются — доступ определяют RLS и политики Storage. Проверка сессии — `getClaims()` (локальная проверка подписи JWT, без сетевого запроса на каждый переход). Функции Vercel в `sin1` рядом с базой. Регистрация в Supabase закрыта, пользователь создаётся вручную. Короткий логин (`kris`) разворачивается в служебный email.

## ADR-017 Внешний вид сайта и PDF разделены
Тема сайта — токены CSS (`src/lib/theme.ts`), расчёт контраста WCAG AA, автоподбор оттенка (светлая тема темнеет, тёмная светлеет), хранение в Supabase (`settings`, ключ `ui`) и кеш в `localStorage` только для устранения «мигания». PDF использует отдельные константы `src/pdf/tokens.ts`; тест запрещает импорт темы в `src/pdf`, а e2e сравнивает страницу PDF в светлой и тёмной теме пиксель-в-пиксель.

## ADR-018 Импорт карт: разбор в браузере
PDF разбираются в браузере специалиста (pdf.js), на сервер уходит только структурированный результат. Персональные данные исходного пациента хранятся только в записи импорта и удаляются вместе с ней. Кандидаты в библиотеку создаются только после явной отметки и подтверждения; повторы объединяются по нормализованному ключу; имя пациента в тексте шаблона блокируется.
